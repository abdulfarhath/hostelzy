## Re-homing a canvas on the new account
An artifact belongs to the account that made it. On the new account:
1. The old owner shares both canvases with the new account (Share → the new email or "anyone with the link") and gives **edit** access if possible. If the new account can edit, keep the same URLs and change nothing in the docs.
2. If it can't edit, create a new Design artifact. Use the Artifact quickstart with intent `design`, then publish with the Design `type_url` and a title like "Hostelzy · Main design".
3. Copy the files in:
   - Read the old canvas's `project/canvas.json` and every `project/*.dc.html` (Artifact `read` with `path`; `list` with scope `files` gives the names).
   - Publish them to the new URL with `root` = that folder and `file_path` = `project/canvas.json`.
   - Upload images (the map screenshots) as assets first and point the boards at the new `/_blob/` URLs.
   - **Fallback:** the main canvas sources are in git, but only partly. `docs/design/v22`, `v23` and `f26-merge/followup` hold the latest changed boards plus full `canvas.json` indexes. The F26 proposal sources are complete in `docs/design/proposal-f26/project/`.
4. Update the canvas URL in CLAUDE.md, START-HERE.md, BOARD.md, HUB.md and the feature files.

## How the boards are made
The boards are generated by Python. The scripts are in `docs/design/f26-merge/scripts/`. The paths inside them point at the old session's scratchpad, so change `SP` / `P` at the top.
- `w1.py` … `w5.py`: the shared helpers (`btn`, `sheet`, `kick`, `head`, `phone`, `NAVS`, building view, …) and the F24/F25 boards. Each later script `exec`s the earlier one up to a marker.
- `f26.py`: the F26 proposal boards (before → after wrappers) and every "after" phone used later. It reads the pre-F26 main boards from a local mirror of the main canvas `project/` folder (`P`).
- `m26.py`: builds the main-canvas F26 merge (updates, retirements, new boards, the resident tab bar on every resident board, counts).
- `f26b.py`: the follow-up (H45–H47, C14, C15, console nav).
- `f27.py`, `v23.py`: F27 boards and the F27 main-canvas merge.
- `peek.py`: prints a board without styles. `f26shot.js`: renders boards to PNG with Playwright (`node f26shot.js <dir> <outdir>`) for a quick check.

How each update ships: prepare `docs/design/vNN/` on branch `design/f26-merge` with a fresh `canvas.json` built on the current main canvas version plus only the changed boards. The hub publishes it. This Design session's own publishes to the main canvas were blocked by its permission check.
