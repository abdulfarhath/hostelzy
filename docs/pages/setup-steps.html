🟩 Supabase

S1 · Run all database steps at onceNOW5 min
  1. Open the file: docs/sql/run-all-pending.sql → click Raw (top right of the file).
  2. Select everything (Ctrl + A, on Mac Cmd + A) → copy.
  3. Go to supabase.com/dashboard → your Hostelzy project → SQL Editor (left menu) → New query.
  4. Paste → click Run. Wait about 10 seconds.
  5. You should see "Success. No rows returned". If Supabase asks "This query has destructive operations, run anyway?", click Run this query (it only replaces old versions of functions).
  6. Check it worked: New query → paste this → Run. Every column must say true: 
    select to_regproc('public.go_live') is not null as onboarding,
       to_regproc('public.confirm_rates') is not null as rates,
       to_regproc('public.deals_hidden') is not null as strikes,
       (select count(*) from pg_indexes where schemaname = 'public'
          and indexname in ('beds_hostel_id_idx','fair_cases_hostel_id_idx')) = 2 as indexes;
  7. Tell the hub: "SQL done, all true".

It's 37 steps (4d → 4zi) in one go. If anything fails, nothing changes: copy the red error and send it to me. It's safe to run twice, even if you already ran some steps one by one.

S2 · Test database (staging), optionalLATER20 min
  1. Supabase dashboard → New project → name hostelzy-staging, region Mumbai, Free plan → set a database password (save it) → Create.
  2. In the new project: Database → Extensions → turn on pg_cron and pg_net.
  3. SQL Editor → New query → paste docs/sql/full-schema.sql (Raw → copy) → Run, once.
  4. Authentication → Sign In / Providers → Third-party Auth → Add provider → Firebase → project ID hostelzy (same as the real project; without it sign-in fails).
  5. Project Settings → API → copy the Project URL and the anon / publishable key. Never the service_role key.
  6. GitHub repo → Settings → Secrets and variables → Actions → New repository secret: HZ_STAGING_SUPABASE_URL = the URL, then HZ_STAGING_SUPABASE_ANON_KEY = the anon key.

🐙 GitHub

G1 · Play upload key + GitHub secretsBEFORE PLAY15 min
  1. On your computer, install Android Studio (it includes Java's keytool) or any Java 17.
  2. Open a terminal (Windows: PowerShell) in a safe folder and run: 
    keytool -genkeypair -v -keystore hostelzy-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
    It asks for a password (choose a strong one, write it down) and your name and city. That's fine.
  3. Turn the file into text and copy it: 
    [Convert]::ToBase64String([IO.File]::ReadAllBytes("hostelzy-upload.jks")) | Set-Clipboard
    That's for Windows PowerShell. Mac: base64 -i hostelzy-upload.jks | pbcopy
  4. GitHub → repo Settings → Secrets and variables → Actions → New repository secret, four times:
    • HZ_UPLOAD_KEYSTORE_BASE64 = paste (the long text)
    • HZ_UPLOAD_KEYSTORE_PASSWORD = your password
    • HZ_UPLOAD_KEY_ALIAS = upload
    • HZ_UPLOAD_KEY_PASSWORD = the same password
  5. Copy hostelzy-upload.jks and the password to a USB drive or password manager. Not in the repo, not in chat.

Losing this key means a new Play listing. Keep 2 copies offline.

G2 · Build the Play Store fileAFTER G12 min + 15 min wait
  1. GitHub → Actions → left list Play Store build → Run workflow → choose production → Run.
  2. Wait for the green tick (~15 min) → open the run → Artifacts → download → unzip → app-release.aab.
  3. Upload it in Play Console (P1, step 5).
G3 · Add a team member (e.g. a marketing intern)WHEN NEEDED2 min
  1. The person signs in to the Hostelzy app once with their Google account.
  2. GitHub → Actions → Team member → Run workflow → their Gmail address → action add (or remove) → Run.
  3. They reopen the app: Me → Settings → Hostelzy team, and the console at farhath.me/hostelzy/app/console/.
G4 · Make the repo privateLAST1 min
  1. GitHub repo → Settings → scroll to Danger Zone → Change visibility → Private.

Read first: on GitHub's free plan, a private repo turns off GitHub Pages. That would take down farhath.me/hostelzy/app/ (privacy policy, delete-account page, invite links and the team console, which Play requires). Do it only after the pages move to hostelzy.in hosting, or with GitHub Pro (~$4/month). APK downloads would then also need a GitHub login. Ask me before you do this.

🔥 Firebase / Google Cloud

F1 · Fix sign-in in the demo appNOW5 min
  1. Go to console.cloud.google.com → APIs & Services → Credentials → top bar: project hostelzy.
  2. Click Android key (auto created by Firebase).
  3. Under Application restrictions → Android apps → Add: 
    app.hostelzy.hostelzy.demo
    with the same SHA-1: 
    46:55:BE:52:35:50:49:2A:E0:A4:AF:CA:26:09:78:5F:08:BD:AA:24
  4. Save. Wait 5 minutes, then try signing in on the demo app.
F2 · Add Play's key fingerprints (or Google sign-in breaks for Play users)AFTER P110 min
  1. Play Console → your app → Test and release → Setup → App signing (or App integrity).
  2. Copy the SHA-1 and SHA-256 of the App signing key, and also of the Upload key.
  3. Firebase console → project hostelzy → ⚙ Project settings → Your apps → Android app.hostelzy.hostelzy → Add fingerprint → add all four.
  4. Click google-services.json to download the new file → attach it here. Build puts it in the app.
  5. Google Cloud → Credentials → Android key → add app.hostelzy.hostelzy again with the App signing SHA-1 → Save.
F3 · SMS OTP loginWHEN A CARD WORKS15 min
  1. Firebase console → bottom-left Upgrade → Blaze (pay as you go; needs a card that works internationally).
  2. Set a budget alert: Google Cloud → Billing → Budgets & alerts → Create budget → ₹500/month → alerts at 50% / 90% / 100%.
  3. Firebase → Authentication → Sign-in method → Add new provider → Phone → Enable → Save.
  4. Tell the hub "OTP is on". Build switches the app's OTP setting and the "Verified" wording.

▶️ Play Console

P1 · Account, app and closed testBEFORE PLAY30 min + 14 days
  1. play.google.com/console → sign up as Personal → pay $25 → verify your identity (ID + phone; can take 1–3 days).
  2. Create app → name Hostelzy, default language English (India), App, Free.
  3. Fill the Dashboard tasks with Brand's pack (docs/brand/play-store.md): icon, feature graphic, screenshots, descriptions. Privacy policy URL: https://farhath.me/hostelzy/app/privacy/. Data safety: ask the hub for the answers.
  4. Test and release → Closed testing → Create track → add 12+ testers (their Gmail addresses, e.g. friends and PG residents).
  5. Create release → upload app-release.aab (from G2) → Save → Review → Roll out.
  6. Testers must keep it installed for 14 days. Then Apply for production.
P2 · Links open the app directlyAFTER P110 min
  1. Copy the App signing key SHA-256 (from F2 step 2).
  2. Send it to the hub. I'll prepare the assetlinks.json file for the root of your farhath.me site (/.well-known/assetlinks.json) and tell you where to put it.

Never send the Supabase service_role key, the upload key file or any password in chat.
